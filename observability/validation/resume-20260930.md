## Retention negative control

Waiting for edge receipt GC proves handoff to the Collector queue, not that a
backend has processed a record. The old retention query could therefore observe
absence before the old record arrived. The strengthened test requires both
`vl_rows_dropped_total` and `vt_rows_dropped_total` to increase after sending the
nine-day-old canary, then verifies the corresponding log and trace are absent.
Missing/invalid metric samples fail closed. No other producer sends to these
isolated stores, so the increments are attributable to the expired canary.

Primary references:
- https://docs.victoriametrics.com/victorialogs/#retention
- https://docs.victoriametrics.com/victoriatraces/#retention

This checks rejection at ingestion for logs/traces. It does not prove that old
on-disk partitions are physically removed at exactly 168 hours. Metrics retention
is configured explicitly, but this test does not separately certify its expiry.

## Destructive-test guard

`prepare.py --dev` now writes `OBSERVABILITY_DEV_ONLY=true` into the disposable
`.env`. E2E requires it, loopback-only binds, no explicit state-path override and
no explicit Docker host/context override. Both the file and effective shell
environment are checked before any request or process-control action. Compose
fault actions use an explicit project, file, project directory and env file.
This prevents common accidental production runs; it is not a sandbox against
maliciously modified files or Docker configuration. Use a fresh local test
checkout and the local Docker daemon only.
